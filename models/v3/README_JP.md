# V3：公表時点をそろえた企業財務情報の追加

V2の株価・出来高・為替・金利・マクロ特徴量に、企業の財務情報を追加します。
対象は現在のTOPIX500・S&P500です。日米別に1・5・20営業日先の調整後終値比率を予測します。
V3は精度改善を保証するものではなく、同じ条件で改善の有無を測るための実装です。

## 情報源

| 市場 | 取得内容 | 制約 |
|---|---|---|
| JP | EDINET API v2の日付別一覧と有価証券報告書・半期報告書・旧四半期報告書・各訂正報告書のXBRL | APIキーが必要。決算短信やTDnetの速報を取得する実装ではない |
| US | SEC companyfactsの標準タグとsubmissionsのアクセッション・受付時刻 | 実連絡先入りUser-Agentが必要。企業独自タグや株式クラス別の値を推測しない |

EDINETは提出時刻＋1暦日、SECは受付時刻＋1暦日を利用可能時刻にします。
SECで正確な時刻が取得できない場合は提出日UTCの0時＋2暦日を使います。
意図的に公表直後の利用を遅らせる保守的な仮定です。
この時刻以前の株価行に財務値を戻して埋める処理はありません。
訂正報告は訂正の利用可能時刻から反映し、過去期間の訂正値でより新しい期間を置き換えません。

XBRLの実際の期首・期末・通貨・連結／単体のスコープを確認します。
セグメント値・予想値の次元、期間や通貨が合わない値、曖昧な同順位の重複値は混ぜません。
企業独自の拡張タグは自動的に標準タグとみなしません。このため取得率が100%になる保証はありません。

## 特徴量

- 総資産の対数、同一期間の利益率、年率換算利益／期末資産・自己資本。
- 自己資本比率、負債比率、年率換算営業CF／期末資産、同程度の期間の前年同期売上成長率。
- 開示済み純株式数と当日の未調整終値からの推計時価総額、利益利回り、簿価時価比率。
- 推計PER・PBRの対数、推計EPSの絶対値の対数と赤字フラグ、財務期間からの日数。
- 各財務特徴量の欠測フラグ。欠測の補完は学習データだけに適合します。

利益・CFは60〜400日の開示期間を採用し、同じ期末では最新開示の最長期間を優先して、
**値×365.25／実日数**で年率換算します。四半期・累計・通期が含まれます。
これはTTMではなく、ROE/ROAも平均残高を分母にした教科書上の指標とは異なります。
連結純資産には非支配持分等が含まれる場合があり、会計基準間の完全な比較可能性は保証しません。

PER・PBR・EPSは販売業者の現在値ではなく、開示済み利益・純資産・純株式数からの推計です。
時価総額も開示後の自社株買い等を即時反映する観測値ではありません。
Yahooの過去終値には後日の分割が反映されるため、取得した分割履歴で当時の価格に戻してから評価指標を計算します。
株式分割は特徴量の日までに起きたものだけを株数に反映します。
分割履歴が不足する場合、日本株で自己株式控除を確認できない場合、米国で複数株式クラスがある場合などは、
これらの評価指標を欠測にします。総資産・利益等から作る指標は利用できます。

## 比較の条件

同じbase_set・モデル・予測期間について2本を推定します。

- `M3_CONTROL`：V2由来の市場・マクロ特徴量だけ。
- `M3_FINANCIAL`：CONTROLの特徴量＋財務特徴量＋欠測フラグ。

M1/M2を選んだ場合も同じ命名規則です。
財務値を確認できる銘柄・学習行にCONTROL側もそろえ、学習サンプルのSHA-256を両者に保存します。
学習には予測起点までに目的変数の終点が到来した行だけを使います。
最低252営業日、通常は直近756の利用可能な学習営業日を使い、毎回再学習します。
light/standardの推定器設定はV2の実装を共用します。
HistoricalMean・OLS・Ridge・Lasso・ElasticNet・RF・XGB・Ensembleを保存します。
HistoricalMeanは特徴量を使わない対照なので、2情報集合で同じ値になるのが正常です。

CONTROLはV2の既存予測をコピーしたものではありません。価格整備・対象銘柄・学習行がV3の比較条件にそろいます。
版をまたいだ差を財務情報だけの効果と解釈しないでください。
現在の構成銘柄を過去学習にも使うため、生存者バイアスが残ります。
価格の後日調整や取得元の訂正も含め、完全な時点整合データベースではありません。

## 初回取得と保存

日本は直近の日から過去へ一覧を確認し、既定で1回730暦日を処理します。
古い日を取得済みならスキップし、直近7日間は再確認します。書類ごとの保存が成功してから日付を完了扱いにします。
米国は会社ごとに受付履歴とcompanyfactsを取得します。新しい定期報告がなければcompanyfactsの再取得を省略します。
新しい提出がcompanyfactsに未反映なら、次回も確認します。
取得元の保持期間外・廃止銘柄・特殊な会計タグなどにより2018年まで履歴がそろう保証はありません。

利用可能な財務情報は、資産・利益の期末から既定550日以内とします。
当日の有効な財務情報・市場特徴量が対象集合の80%未満なら予測を作りません。
取得途中で履歴・カバレッジが足りなければ `BOOTSTRAP` として進捗を保存します。
全期間を確認しても足りない場合は明示的に停止します。収集だけの実行も可能です。

- 財務原数値：`data/fundamentals/v3/{JP,US}/filings/`。書類単位で不変保存。
- 進捗：同フォルダの `scans/`（JP）、`checks/`（US）。
- 予測時点の特徴量：同フォルダの `feature_snapshots/`。予測メタデータからパスとハッシュを参照。
- 予測：`predictions/v3/{JP,US}/`。CSV＋JSON、設定・学習標本・出典を保存。
- 実績：`evaluations/v3/{JP,US}/`。予測元ファイルのハッシュを照合して別保存。

後日同一書類IDの内容が変化した場合は自動上書きせず停止します。訂正書類は別IDとして保持します。
パーサーや特徴量定義を変更する場合は実装版・設定識別子を更新し、既存履歴を削除して合わせないでください。

## コマンド

リポジトリ直下で実行します。必要なSecretsは `INSTALL_V3.md` を参照してください。

```bash
python -m models.v3.main --market JP --base-set M1 --sync-only
python -m models.v3.main --market JP --base-set M3 --profile light
python -m models.v3.main --market US --base-set M3 --profile light
python -m models.v3.main --market JP --base-set M1 --no-sync
python -m models.v3.demo --market BOTH
```

`--no-sync` は保存済み財務値を利用します。市場データ取得は行うためオフラインではありません。
完全オフラインの接続確認はdemoを使います。出力先は `output/demo/v3/` で本番予測とは分離します。
CLI全引数は `python -m models.v3.main --help` を参照してください。
